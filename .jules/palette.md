## 2025-01-31 - Flashcard Interactive Component Keyboard Accessibility
**Learning:** For interactive components like flip cards built with `<div>` elements instead of semantic buttons, they must be explicitly mapped to the keyboard focus tree (`tabindex="0"`) and assigned a role (`role="button"`) to support standard screen-reader behavior. When binding global keyboard event listeners (like Arrow navigation or Space/Enter to trigger actions), they must be defensively scoped to the active component or tab to prevent cross-view side effects, such as unintended triggering on other pages.
**Action:** Next time I build or refactor an interactive component in Vanilla JS, I will ensure explicit focus management via `tabindex` and `role`, and carefully scope any global event listeners (like `keydown`) to the active tab state before executing UI actions.
