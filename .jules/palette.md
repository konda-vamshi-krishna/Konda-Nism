## 2024-05-24 - Interactive Component Accessibility and Keyboard UX
**Learning:** For interactive components containing visually meaningful text (like study flashcards), using `aria-label` will completely overwrite the inner text for screen readers, hiding the actual educational content. Additionally, global keyboard shortcuts in Single Page Applications must be tightly scoped to the active view to avoid unintended actions in other tabs, and must selectively ignore input elements (like form fields or buttons) so default browser interactions remain intact.
**Action:** When adding instructions to visually meaningful elements, use `.sr-only` to visually hide the instructional text and link it to the container using `aria-describedby` instead of `aria-label`. Always scope global `keydown` listeners to the currently visible container (e.g., checking for `.active` class) and skip execution if the `document.activeElement` is a form control or link.
