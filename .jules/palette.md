## 2024-11-05 - Interactive Component Keyboard Navigation in PWA Tab Interfaces
**Learning:** Adding global keydown listeners for keyboard accessibility (like Space/Enter for clicks and Arrows for navigation) in interactive components such as flashcards requires scoping the listener to the component's specific tab content area (`.tab-content.active` ID match). Failing to do so causes unintended behaviors when using keyboard navigation in other views. Additionally, we must ignore events originating from form elements (`INPUT`, `SELECT`, `TEXTAREA`) to preserve default form control behaviors.
**Action:** When implementing keyboard shortcuts for non-standard interactive components in this Vanilla JS PWA, always scope the logic to the currently active tab ID and explicitly filter out events originating from input-like tags before triggering `preventDefault()`.
## 2024-11-05 - Ignore Buttons and Links in Global Keydown Handlers
**Learning:** When using global keydown handlers on a tab, it's not enough to just ignore form inputs (`INPUT`, `SELECT`, `TEXTAREA`). We must also ignore focusable elements like `BUTTON` and `A`, otherwise intercepting `Space` or `Enter` will prevent standard button or link activation if the user navigated to them via `Tab`.
**Action:** Extend the ignored tag list to include `BUTTON` and `A` when adding custom interactive keyboard shortcuts via global listeners.
